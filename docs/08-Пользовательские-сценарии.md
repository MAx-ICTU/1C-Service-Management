# 08. Пользовательские сценарии v0.2

UC-R1-01. Диспетчер создаёт клиента/оборудование, выбирает их в заявке, вводит описание, адрес и контакт. Сохраняет черновик, затем принимает. Результат: Новая, время регистрации, история. Ошибка связей/полей оставляет черновик и показывает причины.

UC-R1-02. Диспетчер выбирает активного инженера с пользователем ИБ. Назначение → Назначена. Переназначение до начала требует причины. Алгоритм выбора и расписание отсутствуют.

UC-R1-03. Инженер входит под собственной учётной записью, открывает своё назначенное обращение, начинает. Вводит диагноз/заключение, работы с количеством и суммарными часами, итог. Промежуточное сохранение допустимо. Чужая заявка не открывается даже по прямой ссылке.

UC-R1-04. Диспетчер читает результат, закрывает. Без заключения/итога или необходимых работ — отказ без частичного закрытия. При «не выявлена» без работ требуется пояснение. Закрытые факты не редактируются.

UC-R1-05. Руководитель выбирает оборудование/период в истории; видит даты закрытия, инженеров, диагноз и работы, переходит в заявку. Инженер видит только доступные ему закрытые обращения.

UC-R1-06. Администратор создаёт пользователей ИБ и роли последовательно, связывает UUID инженера. Закрывает текущий сеанс перед пакетным Конфигуратором/входом следующего пользователя. Выгрузку проверяет на отдельной ИБ по 13, фиксирует протокол и коммит.

# 10. Процесс разработки Windows v0.2

До утверждения ревью: только документы/планы/Git. Следующие действия описаны для последующего выполнения, не выполнены сейчас.

## Разделение автоматизации

| Категория | Действия | Ограничение |
|---|---|---|
| Полностью автоматизируемые Codex при доступных файловых/Git инструментах | Документация, ревью исходников, изменение выгруженных текстов модулей после разрешения, сравнение файлов/коммитов, протоколы, локальный Git | Код только после утверждения; GitHub после выбора remote/доступа |
| Частично автоматизируемые | Пакетная выгрузка/загрузка Конфигуратора, сверка выгрузки, запуск проверки/тестов, сбор результатов, исправление | Требуются закрытый сеанс, валидный экспорт, доступ к установленной платформе; диалоги/учебные ограничения могут требовать человека |
| Вручную через Конфигуратор в данном процессе | Создание первой ИБ/конфигурации, объектов/реквизитов/форм/ролей, выбор свойств, синтаксический контроль, обновление БД/подтверждение изменений, интерактивная проверка, управление пользователями | Для этих операций не заявлена надёжная автоматизация текущими инструментами; EDT/COM/агент не используются |

Это разделение практического процесса, а не утверждение, что платформа никогда не поддерживает пакетную проверку. Дополнительные CLI-параметры проверки не добавляются до подтверждения в справке именно установленного релиза.

## Папки репозитория

docs/ — документация; src/config/ — полный штатный экспорт после первого разрешённого задания; tests/protocols/ — результаты; ib/dev/ и ib/roundtrip/ — локальные базы, игнорируются Git; backups/ и logs/ — локальные, игнорируются. На этапе 00 уже созданы пустые ib/dev и ib/roundtrip; src/config ещё отсутствует, так как целевой экспорт не получен.

## Воспроизводимый цикл

1. Утверждённая задача с составом объектов/полей и тестами; ветка stage/NN-description от актуального main.
2. Закрыть пользовательский сеанс; резервировать ИБ/конфигурацию штатно или копированием закрытой базы.
3. Создать/изменить метаданные в Конфигураторе; сохранить. Не конструировать произвольный XML.
4. Выгрузить всю конфигурацию в чистый временный каталог по 13; после проверки заменить управляемый экспорт src/config, включая удалённые файлы.
5. После разрешения кодирования Codex меняет только тексты модулей существующего экспорта. Новые метаданные/формы сначала создаёт Конфигуратор, чтобы получить корректные UUID/структуру.
6. Закрыть сеанс; загрузить полный экспорт в отдельную проверочную ИБ либо копию разработки. Не загружать экспорт неясного происхождения.
7. Открыть Конфигуратор; выполнить синтаксический контроль изменённых модулей и штатную проверку конфигурации, сохранить сообщения.
8. Обновить конфигурацию БД отдельной командой; проверить список структурных изменений до подтверждения.
9. Запустить Предприятие, выполнить тесты этапа по очереди под ролями; закрыть перед следующей пакетной операцией.
10. Исправление → повтор 3–9; финальная выгрузка именно принятого состояния, diff, протокол.
11. Commit и push ветки, PR с результатами/ограничениями; утверждение → merge и тег. Не помечать этап завершённым лишь по коммиту.

Нельзя одновременно запускать интерактивный Конфигуратор и пакетный над одной учебной ИБ. Нельзя считать /LoadConfigFromFiles автоматическим обновлением БД: это отдельный шаг. Код возврата оболочки дополнить сообщениями платформы и проверкой состояния; при ошибке не переходить дальше.

Для чистого экспорта использовать новый каталог, чтобы старые XML удалённых объектов не остались в src/config. Перед заменой сверить абсолютные пути внутри репозитория и резервировать экспорт; удаление по широким шаблонам вне проекта запрещено. Git фиксирует удаление через git add -A -- src/config.

Исходники штатного формата и учебная ИБ — разные артефакты. .cf/.dt могут быть локальной резервной копией, но не заменяют обозримый текстовый diff. XML/BSL сохраняют байты выгрузки через .gitattributes; модули не нормализуются без проверенного round-trip.

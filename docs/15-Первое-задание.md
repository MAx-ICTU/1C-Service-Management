# 15. Первое задание: пустая конфигурация и подсистема Сервис

Статус: разрешено пользователем 08.10.2026, частично выполняется в stage/00-bootstrap. Реальное состояние и ручные проверки — в tests/protocols/stage-00.md. Созданы две пустые файловые ИБ; именованный корень и подсистема пока требуют ручного действия. На этом задании нет кода, справочников, документов, форм, общих модулей и ролей.

Режим совместимости не угадывается по номеру платформы: оставить исходное доступное значение, записать точный выбор в протокол; не переводить произвольно в 8.3.

## Последовательность пользователя в Windows

1. Убедиться, что этап разрешён; выбрать место локальной учебной ИБ (рекомендуется ib/dev внутри проекта, оно игнорируется Git). Не использовать реальную базу.
2. В списке запуска 1С «Добавить» → создание новой ИБ → создание без конфигурации для разработки новой конфигурации. Название списка «СервисТех — учебная разработка», расположение на этом компьютере, файловый каталог. Выбрать установленную 8.5.1.1150.
3. Открыть «Конфигуратор» этой базы. Если дерево ещё не открыто — «Конфигурация → Открыть конфигурацию».
4. Выделить корень, открыть свойства, задать имя/синоним/версию/основной режим запуска из таблицы. Записать фактический режим совместимости и версию через «О программе».
5. В «Общие → Подсистемы» добавить одну подсистему Сервис, задать свойства. Не добавлять вложенную подсистему и не писать модуль.
6. Сохранить конфигурацию. Выполнить штатную проверку конфигурации; модулей ещё нет, поэтому «проверка синтаксиса модулей» не является доказательством готовой логики.
7. «Конфигурация → Обновить конфигурацию базы данных». Проверить отсутствие неожиданных объектов, подтвердить изменение.
8. Запустить Предприятие для проверки открытия учебной базы. Пустая подсистема может не отображаться в интерфейсе, поскольку у неё нет команд; это не дефект. Проверять её существование/свойства в дереве и экспорте.
9. Закрыть Предприятие и Конфигуратор. Создать новый пустой каталог выгрузки; выполнить ручную/пакетную выгрузку из 13.
10. Сохранить полный экспорт в src/config без самодельных XML. Открыть отдельную пустую roundtrip-ИБ, загрузить экспорт, проверить/обновить БД; сверить корень и Сервис. Не использовать второй одновременный сеанс.
11. Заполнить tests/protocols/stage-00.md, сделать diff/коммит и опубликовать этап после задания GitHub remote.

## Критерии проверки

- exe/«О программе» 8.5.1.1150, учебная, файловое расположение.
- Имя/синоним/версия корня точно соответствуют таблице.
- Ровно одна созданная верхнеуровневая подсистема Сервис, состав пуст; остальные бизнес-объекты отсутствуют.
- Все модули пусты/отсутствуют; код 1С не добавлен.
- Конфигурация сохранена и БД обновлена без ошибок; Предприятие открывается.
- Экспорт произведён платформой, формат/файлы/UUID записаны; обратная загрузка в другой базе прошла, UUID не пересозданы.
- Git diff содержит экспорт+протокол, не 1CD/.dt/пароли/временные файлы. Нет необъяснимых изменений.

## Git — примеры будущего выполнения

Команды выполнять из корня репозитория outputs, не из src/config. Перед ними проверять git status и актуальный main. Этап начат частично; готовность к приёмке пока не подтверждена.

```text
git switch -c stage/00-bootstrap
git status --short
git diff -- src/config tests/protocols/stage-00.md
git add -A -- src/config tests/protocols/stage-00.md
git commit -m "chore: bootstrap learning configuration and service subsystem"
git push -u origin stage/00-bootstrap
```

Последняя команда требует настроенного remote/аутентификации. PR описывает созданные объекты, платформу, ручные проверки и round-trip. Тег stage-00-accepted создаётся только после приёмки, не до неё. Если Git-автор пользователя ещё не настроен, согласовать его либо явно использовать технического автора Codex; не придумывать личные имя/email.

# 05. Модель данных R1 v0.2

## Состав метаданных

Конфигурация УправлениеСервиснойКомпанией, синоним «1С: Управление сервисной компанией». Подсистемы верхнего уровня: Сервис (первая), НормативныеДанные, Отчеты. Справочники Клиенты, Оборудование, Инженеры, ВидыРабот. Документ ЗаявкаНаОбслуживание, синоним «Заявка на обслуживание», без проведения. Перечисление СтатусыЗаявок. Регистр сведений ИсторияСостоянийЗаявок. Отчёт ИсторияОбслуживанияОборудования. Роли Администратор, Диспетчер, Инженер, Руководитель.

Только перечисленные объекты входят в R1. Создаются через Конфигуратор, затем выгружаются платформой; это спецификация, не XML-конфигурация.

Обозначения: ! — обязательно; ? — необязательно. Строка(N), Число(P,S), Дата(Дата/ДатаВремя), Булево, УникальныйИдентификатор — типы платформы. Ссылки указаны полностью. Проверка обязательности — серверная в будущей реализации. Стандартные Код/Наименование справочников не создаются вторично.

## Справочники

Все четыре: без иерархии, без владельца, Код Строка(9), Наименование Строка(150); код авто, наименование обязательно; Активен Булево, начальное значение Истина через будущую обработку создания/форму. Пометка удаления стандартная. Неактивные не выбираются в новых заявках, исторические ссылки сохраняются.

Политика идентификаторов оборудования — Q-R1-03: рекомендуются уникальный непустой инвентарный номер внутри клиента и предупреждение при одинаковом производитель+серийный номер. В R1 не молча запрещать совпадение неизвестных производителей. Идентификатор пользователя ИБ инженера должен быть уникальным среди активных инженеров; выбирать существующего пользователя через настройку администратора, не вводить UUID наугад.

## Перечисление СтатусыЗаявок

Точные значения: Черновик, Новая, Назначена, ВРаботе, Закрыта, Отменена. Подписи: «Черновик», «Новая», «Назначена», «В работе», «Закрыта», «Отменена». Новая запись — Черновик. Редактирование поля статуса напрямую запрещено, используются команды документа 04.

## Документ ЗаявкаНаОбслуживание

Номер — Строка(9), автоматическая нумерация, периодичность в пределах года. Дата — стандартная ДатаВремя создания документа. Проведение запретить; движения накопления отсутствуют. Статус процесса не равен признаку Проведен.

|---|---|---|

| Оборудование | СправочникСсылка.Оборудование | ! при принятии; принадлежит клиенту |
| Инженер | СправочникСсылка.Инженеры | ! при назначении |

Табличная часть ВыполненныеРаботы:
- ИдентификаторСтроки — УникальныйИдентификатор!, стабильный, не номер строки.
- ВидРаботы — СправочникСсылка.ВидыРабот!, активный при добавлении.
- Количество — Число(15,3), положительное!, единица R1 — условная операция без пересчёта единиц.
- ФактическиеЧасы — Число(10,2), неотрицательное!, 0 допустим.
- Комментарий — Строка(300)?.

Итог часов — сумма ФактическиеЧасы строк, не умножается повторно на Количество. Для двух операций одной строки инженер вводит суммарные часы. Цены, суммы продаж, материалы и деньги отсутствуют.

Формы: ФормаДокумента, ФормаСписка (управляемые). Клиент/оборудование/обращение доступны диспетчеру до принятия; после принятия идентификация фиксируется. Диагноз/работы/итог доступны своему инженеру во ВРаботе. Диспетчер читает результат и закрывает; администратор имеет доступ, но соблюдает переходы/терминальность.

## Регистр сведений ИсторияСостоянийЗаявок

Непериодический, независимый, не подчинён регистратору. Измерения: Заявка (ДокументСсылка.ЗаявкаНаОбслуживание), НомерСобытия (Число(10,0)). Ресурсы: Момент (ДатаВремя), СтарыйСтатус/НовыйСтатус (ПеречислениеСсылка.СтатусыЗаявок), СтарыйИнженер/НовыйИнженер (СправочникСсылка.Инженеры), Автор (УникальныйИдентификатор), ВидСобытия (Строка(40)), Причина (Строка(300)). Реквизиты: ИдентификаторОперации (УникальныйИдентификатор), ВерсияДанных (Число(10,0)).

Запись — только серверным сервисом в транзакции изменения заявки. Виды событий фиксированным контрактом: Принятие, Назначение, Переназначение, Начало, Закрытие, Отмена. Номер монотонен внутри заявки. Регистр используется для переходов/назначений и идентичного повторного запроса, а не копирует все работы. Обычный пользователь не имеет прямых прав записи. Инженер читает события только своих доступных заявок.

## Подсистемы и связи

НормативныеДанные: все четыре справочника. Сервис: ЗаявкаНаОбслуживание, перечисление/регистр как внутренняя зависимость (без команд прямого редактирования). Отчеты: ИсторияОбслуживанияОборудования. Справочник оборудования доступен из заявки/отчёта навигацией.

Клиент 1:N оборудование/заявки; оборудование 1:N заявки; инженер 1:N заявки; заявка 1:N строки работ/события. Источник фактов — документ; источник текущего состояния — его статус; история только аудирует смену. Накопительные регистры R1 не нужны.

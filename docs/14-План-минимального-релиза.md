## Детали задач и зависимости

01: сначала Клиенты, Инженеры, ВидыРабот, затем Оборудование с типом ссылки Клиенты; все включить в НормативныеДанные. Справочники инженеров создаются до назначения, но привязка пользователей/полные права проверяются на 03.

02: сначала перечисление, затем документ и табличная часть, затем независимый регистр со ссылкой на документ. После выгрузки корректного каркаса — серверные проверки/команды и управляемая форма. Приём только после валидных полей; назначение вручную; диагноза/работ нет в отдельных документах.

03: полный администратор, затем права диспетчера/руководителя и ограниченный инженер. Создать не менее двух инженеров/учётных записей; test прямой ссылки/отчёта обязательно. Один сеанс закрывается между входами.

04: чтение фактов из заявки/табличной части; не создавать накопительный регистр истории. Не соединять строки работ со всеми строками статусов при подсчёте часов.

05: новая ИБ из выгрузки, полный синтаксис/проверка, обновление/запуск, проверка всех R1-TC, анализ Git diff. Указать невыполненные промышленные проверки; не маскировать их в сводном «всё пройдено».

## Правило завершения этапа

Объекты соответствуют утверждённой задаче; штатная выгрузка отражает фактически проверенную конфигурацию; тесты/ошибки отражены в протоколе; коммит опубликован в выбранном GitHub; PR/результат зафиксированы. До выбора GitHub этап может иметь только статус «Зафиксирован локально, публикация ожидается». Публикация документации не заменяет одобрение реализации.

# 06. Архитектура v0.2

## Учебный контур

Одна самостоятельная управляемая конфигурация, файловая ИБ Windows, платформа 8.5.1.1150 учебная. Основной режим запуска — управляемое приложение; Конфигуратор обычный, EDT отсутствует. Файл базы 1CD обслуживает платформа, клиент не изменяет его содержимое напрямую.

«Серверный контекст» в описании модулей означает место исполнения логики платформы, а не наличие выделенного сервера 1С. В файловом варианте логическое разделение клиент/сервер сохраняем для последующего переноса. Схема текущего стенда: управляемый клиент/логика платформы → файловая ИБ. Кластера/СУБД/HTTP-сервисов R1 нет.

## Разделение ответственности

| Клиент формы | Серверный контекст |
|---|---|
| Ввод, отбор, навигация, подсказки, вывод ошибок | Чтение/запись ИБ, проверка ролей и принадлежности |
| Подготовка параметров команды | Переход статуса, назначение, обязательность, даты/версия |
| Предварительные проверки для удобства | Повторная окончательная проверка, транзакция, история |
| Запрос отчёта | Запросы СКД и ограничение доступных данных |

Будущие общие модули: ЗаявкиСервис (серверный, правила команд), ДоступСервис (серверный, права/связь пользователя), ИсторияЗаявокСервис (серверный, неизменяемая история). Они не создаются в первом задании пустой конфигурации. Не включать прямой вызов всех процедур клиентом и не использовать привилегированный режим для обхода права инженера.

Серверный обработчик записи документа также проверяет терминальность/поля/права, чтобы форма и будущие внешние команды не стали обходом. Для смены статуса закрываем прямое редактирование реквизита, но защита формы дополняется серверной проверкой.

## Права

| Операция | Админ | Диспетчер | Инженер | Руководитель |
|---|---|---|---|---|
| Справочники | Изменение | Изменение | Чтение связанного оборудования/клиента/видов работ | Чтение |
| Принятие, назначение, отмена | Да | Да | Нет | Нет |
| Начало, диагноз/работы/итог | Да | Чтение | Только своя заявка ВРаботе | Чтение |
| Закрытие | Да | Да | Нет | Нет |
| История/отчёт | Все | Все | Только собственные доступные заявки | Все |
| Пользователи ИБ | Да | Нет | Нет | Нет |

Инженер получает ограничения по записи документа и истории, связанные с его ИдентификаторПользователяИБ. Групповая роль «Инженер» не даёт глобального чтения заявок. После переназначения до начала старый инженер теряет доступ; закрытую собственную заявку читает, не редактирует. Расшифровка/экспорт отчёта соблюдают ту же политику. Последовательная проверка четырёх ролей возможна в одном сеансе по очереди.

## Атомарность и будущая конкурентность

Команда: проверка права → блокировка заявки → сравнение ВерсияДанных → проверки → запись заявки и истории → фиксация. Сервер сам определяет автора/время. Повтор ИдентификаторОперации с тем же объектом/командой возвращает прежний итог; повтор с отличающимися параметрами — конфликт. Для полноценного сравнения параметров будущая реализация использует соответствующие значения сохранённого события, не только наличие UUID.

Один сеанс не позволяет доказать правильность гонки; сейчас проверить откат ошибки/повтор/конфликт сохранённой версии. Реальные параллельные проверки отложены, что записано в 09/16.

## Регламентные задания и интеграции

В R1 регламентные задания не создаются: автоматический SLA/ТО исключены. Нет обещания автономной обработки при закрытых клиентах файловой учебной ИБ. Позднее проектировать фоновые задания на коммерческом контуре и проверять ограничения его лицензирования/режима.

Будущие API/мобильный клиент/уведомления/AI будут вызывать серверные бизнес-команды. Сейчас не создаются HTTP-сервисы, очереди сообщений, токены и заглушки AI.

## Путь коммерческого переноса

1. Выбрать коммерческую поддерживаемую платформу не ниже необходимых возможностей исходной 8.5.1 и лицензии; не обещать загрузку формата 8.5 в более старую 8.3.
2. Восстановить штатную конфигурацию/копию демоданных в отдельной коммерческой тестовой ИБ; проверить формат, режим совместимости, UUID и схемы данных.
3. Выбрать файловый либо клиент-серверный промышленный профиль по обследованию, настроить резервирование и права.
4. Выполнить синтаксис/проверку/функциональные тесты, параллельные команды/блокировки, RLS, нагрузку и восстановление.
5. Расширять склад/SLA/финансы отдельными утверждёнными этапами, с миграциями и новой приёмкой.

Переносимость проектная; до выполнения этих шагов не считается доказанной. Лицензирование и назначение учебной версии описаны в [официальных ответах 1С](https://v8.1c.ru/priobretenie-i-vnedrenie/otvety-na-tipovye-voprosy-po-litsenzirovaniyu-1s-predpriyatiya-8/).

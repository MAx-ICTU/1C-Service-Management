## Отчёты

Общие параметры: период [начало включительно; конец не включительно), организация в будущем расширении, доступные пользователю клиенты/инженеры. При нулевом знаменателе выводить «не применимо». R-13 для неактированных заявок выводит отдельно предварительную стоимость и отрицательный финансовый результат до признания выручки. Не смешивать предварительную стоимость работ с признанной выручкой. Общие накладные расходы не распределяются в MVP (Q-12).

Для R-12 несколько инженеров не получают по одной полной «закрытой заявке» каждый: счётчик заданий индивидуальный, счётчик заявок относится к последнему ответственному заданию. SLA остаётся показателем заявки, а не персональной оценкой причин задержки.

## АРМ диспетчера

Верхняя строка: момент последнего обновления, период выездов, территория, переключатель «Мои/Все», поиск по номеру, клиенту, оборудованию. Счётчики имеют расшифровку и могут пересекаться: новая критическая заявка входит в две очереди.

Слева — очереди «Новые», «В работе», «Просроченные», «Высокий/Критический приоритет», «Ожидание», «ТО». В центре — список: номер, клиент, оборудование, приоритет, статус, оставшееся время реакции/решения, инженер, следующий выезд. Справа — карточка выбранной заявки с контактами, описанием, документами и рекомендациями инженера. Внизу — интервальный календарь инженеров и ближайшие выезды.

Команды: принять, изменить классификацию с причиной, показать кандидатов, назначить/переназначить, создать выезд, зарегистрировать реакцию, согласовать паузу, возобновить, проверить готовность закрытия, закрыть, открыть историю. Перетаскивание выезда меняет только план после серверной проверки пересечений. Команда отказа показывает конкретные причины, например «По строке 2 использовано 1 шт., списано 0 шт.».

Обновление по запросу и каждые 60 секунд без сброса выделения; это рекомендуемый интервал Q-14. Само обновление не меняет документы. Отсчёт показывает серверный срок в часовом поясе пользователя и признак устаревших данных.
